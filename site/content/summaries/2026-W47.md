The project went from an idea to working tooling. It decided how myelin
projects should get a public site that maintains itself, planned the build,
and built it: a site generator, a pull-request check, two writing skills, and a
tessl package any myelin project can opt into. This repository is now opting
in as the first pilot.

## Decision
- Each myelin project can opt into a public site with two audiences: people
  who use its outputs, and stakeholders following its progress. The
  stakeholder story comes from the git history, per-PR entries and a weekly
  summary, and it replaces private weeknotes. (#1, docs/adr/0001-project-site.md)
- The build plan was reviewed over three rounds and landed, with Hugo to be
  confirmed by a spike. (#2, plans/0001-project-site.md)

## Site tooling
- Hugo was confirmed as the site generator. (#3)
- The content model and contracts were specified. (#4)
- The core build now turns the git history into an explored, decided, built,
  shipped timeline, alongside per-PR entries, summaries and upcoming work.
  (#8)
- Upcoming work comes from GitHub issues through a swappable adapter, and
  reference docs come from Python docstrings. (#5, #6)
- A check fails any pull request that lacks its entry, or a weekly summary
  that is due. (#7)
- An optional Claude Code hook stops a pull request being raised before its
  entry exists. (#9)

## Writing skills
- `site-writing` writes the per-PR entry and the weekly summary under the
  public content rules. (#10)
- `site-update` keeps the overview, guides and docstrings in line with the
  code. (#11)

## Packaging
- The workflow templates and this repository's own test workflow were added.
  (#12)
- The tooling is packaged as a tessl tile that survives the registry's
  file-type rules, with a one-command opt-in script. (#13)
