The tooling met real projects. This repository now publishes its own site, the
first release went out on the tessl registry, and a second project's pilot
showed that opting in assumed one way of installing tessl tools. The team
decided to drop that assumption and built the change, so any project can now
opt in. The pilots also raised six open questions, now tracked as issues, and a
new site layout has been proposed.

## Pilot
- proj-site now publishes its own project site, with an overview and two
  guides, and every merge deploys it to GitHub Pages. (#14)
- The site title links back to the project's home page wherever the site is
  hosted. (#15)
- When an entry is missing, the pull-request check suggests a file named after
  the pull request's branch, matching what the writing skill creates. (#16)
- The project's own tests give the same result on pull requests as everywhere
  else. (#26)

## Packaging
- Opting in and building the site became a `site-setup` skill, so the
  published package carries the build, adapters and scripts as well as the
  writing skills. (#17)
- Projects installing from the registry now get the workflow templates too;
  version 0.1.1 carries the fix. (#18)
- The site's workflows now install the proj-site tools themselves, so a project
  can opt in however it installs its tessl tools; version 0.2.0 carries this
  once published. (#25, #27, #28)

## Completed
- This repository's opt-in pilot, including the GitHub Pages deploy (#14–#16)
- The first registry release, and its follow-up fix (#17, #18)
- ADR 0002 accepted and plan 0002 delivered (#25, #27, #28,
  docs/adr/0002-tile-distribution.md, plans/0002-tile-distribution.md)
